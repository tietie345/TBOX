# TBOX 录音转写升级方案：说话人分离 + 高保真录制 + 文字稿整理

> 目标：对标豆包 / 腾讯会议的录音转写体验 —— **稳定完整录制，停止后自动处理出完整、准确、带说话人区分的可编辑文字稿**。
> 不做实时流式（用户明确不需要）；不影响截图、录屏、标注、贴图、OCR、翻译等任何其他功能。

## 一、现状与差距

| 维度 | 现状 | 差距 |
|------|------|------|
| 录音格式 | 44.1kHz 单声道 AAC（有损压缩） | 编码损失影响识别与分离精度 |
| 说话人 | `speakerName` 恒为"我" | 无说话人分离，会议场景不可用 |
| 文字稿整理 | 仅规则聚合（句末标点/停顿/时长） | 无语气词清理，无说话人感知的断句 |
| 引擎 | WhisperKit 1.1.0（本地 large-v3，质量已达标） | 保留，作为转写主引擎 |

## 二、技术选型结论

**核心新增：Argmax SpeakerKit（pyannote CoreML 说话人分离）**，与现有 WhisperKit 同源（argmax-oss-swift 仓库三件套之一），纯 Swift + CoreML，完全本地运行。

选型验证结论（2026-09 调研）：
- 本地 vendored 的 ArgmaxCore / WhisperKit 与 argmax-oss-swift 最新主线（ea872ff, 2026-08-13）**几乎完全一致**（ArgmaxCore 零差异，WhisperKit 仅 1 个未使用文件有差异），SpeakerKit 源码可直接 vendor 引入，无 API 冲突。
- SpeakerKit 三件模型（segmenter + embedder + clusterer）合计 **约 11 MB**，首次下载负担极小。
- 不引入本地 LLM（Qwen MLX 等）：体积与复杂度过大，本期用确定性规则整理代替，LLM 后处理作为后续可选扩展。
- 不更换降级引擎（SFSpeechRecognizer）：macOS 26 SpeechAnalyzer 需要系统版本门槛，当前部署目标 macOS 14，保持现状。

## 三、总体架构

```
录音（Layer 1）  48kHz 单声道 PCM .caf（无损）
                      │ 停止后
                      ▼
        ┌─────────────────────────────┐
        │  双引擎并行（Layer 2）        │
        │  ├─ WhisperKit large-v3      │ → 词级片段 + 文本 + 语言
        │  └─ SpeakerKit (pyannote)   │ → [start, end, speakerId]
        └─────────────────────────────┘
                      │
                      ▼
        对齐合并（Layer 3）按时间重叠最大原则给词段标注说话人
                      │
                      ▼
        文字稿整理（Layer 4）说话人感知聚合 + 语气词清理
                      │
                      ▼
        结果窗口：说话人徽标 · 时间戳 · 三种格式导出（txt/srt/md）
```

## 四、分层设计

### Layer 1：高保真稳定录制

- `AVAudioRecorder` 改为 **48kHz / 16-bit / 单声道 Linear PCM**，容器 `.caf`。
  - 48kHz 是 macOS 麦克风原生采样率，避免双重重采样；
  - PCM 无损，Whisper 与 pyannote 均以 16kHz 工作，由各自加载器统一降采样，源头质量最高；
  - 体积约 5.5 MB/分钟，可接受（质量优先）。
- 文件名模式不变：`录音转写_<时间戳>.caf`；旧 m4a/wav 录音仍可正常打开转写。
- 记录列表（设置页"记录"）扩展支持 `.caf` 扩展名。
- 稳定性保障沿用现有机制：停止后校验音频帧数、原子写入转写快照、快照带文件大小+修改时间校验。

### Layer 2：双引擎并行

- **WhisperKit**（现有）：`chunkingStrategy: .vad` + 词级时间戳，输出改为**词级片段 + 全文 + 语言**（不再在引擎内部聚合，聚合移至 Layer 3/4 以便先标注说话人）。
- **SpeakerKit**（新增，`Recording/SpeakerDiarizer.swift`）：
  - `PyannoteConfig(downloadBase: ~/Library/Application Support/TBOX/Models)`，模型与 Whisper 模型同目录管理；
  - 首次使用自动下载（约 11 MB）；
  - `diarize(audioArray:)` 输出 `[SpeakerTurn]`（start/end/speakerID）；
  - **失败降级为无说话人标注**（转写不中断），只记日志。
- 两个引擎 `async let` 并行执行，总耗时 ≈ max(两者)，而非相加。

### Layer 3：对齐合并（`Recording/TranscriptionAligner.swift`）

- 对每个词级片段，取**时间重叠最大**的说话人段标注 speakerID（与 SpeakerKit 官方 `.segment` 策略同思路）；
- 无重叠词段继承前一说话人；
- **说话人修剪**：总发言时长过短的说话人（< 8 秒且 < 3% 总发言）并入邻近说话人，抑制 pyannote 对噪声/口头禅的误分裂；
- 仅 1 个有效说话人时全部回落为"我"（独白场景不显示噪音标签）。

### Layer 4：文字稿整理（`Recording/TranscriptPolisher.swift`）

确定性规则（可测试、可回滚、无幻觉风险）：
- **说话人感知聚合**：句段聚合沿用现有规则（句末标点/停顿≥0.85s/时长/字数），但**不在说话人变化处合并**；
- **纯语气词句段清理**：仅由"嗯/呃/啊/哦/…"组成的句段剔除（Whisper 在静音处的常见幻觉产物）；
- 中英文间距规范化沿用现有 `joined` 逻辑。

LLM 后处理（错字修正、语义分段、纪要生成）为**后续可选扩展**，本期预留 `TranscriptPolisher` 扩展点，不在范围内。

### 结果窗口（`RecordingTranscriptionResultWindow.swift`）

- 逐句视图头部升级：`说话人 1 · 00:12`（现有结构已支持，标签内容变化）；
- 新增**导出按钮**：NSSavePanel + 格式选择（`.txt` 带说话人时间戳 / `.srt` 字幕 / `.md` Markdown）。

## 五、数据格式兼容

- `RecordingTranscriptionSegment` 新增 `speakerID: Int?`（nil = 未标注）；
- 自定义 Codable：解码用 `decodeIfPresent`，**旧版转写快照（无 speakerID 字段）可正常读取**；新快照旧版本读取时未知字段自动忽略，双向兼容；
- 快照版本号维持 2，不破坏已有缓存。

## 七、验证计划

1. `swift build -c release --product TBOX` 全量编译（含 SpeakerKit）；
2. `run_smoke_tests.sh`：现有 6 组 smoke + 新增 `SpeakerPipelineSmoke`（对齐、修剪、说话人感知聚合、语气词清理、Codable 向后兼容、SRT/MD 格式化）；
3. 手工验收：真实双人对话录音 → 停止 → 自动转写 → 结果窗口出现"说话人 1/2"标注 → 导出三种格式。

## 八、风险与对策

| 风险 | 对策 |
|------|------|
| pyannote 误分裂（独白被拆成多人） | 说话人修剪阈值 + 单说话人回落"我" |
| SpeakerKit 模型下载失败（网络） | 失败降级为无标注转写，不中断流程 |
| 双引擎并行内存压力 | Whisper large-v3 ≈1.5GB + SpeakerKit ≈0.2GB，现代 Mac 可承受；转写完成后 SpeakerKit 模型可卸载 |
| 长录音（1h+）PCM 体积 | 5.5MB/min；后续可选自动压缩归档，本期质量优先 |
