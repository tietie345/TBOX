## 一、架构总览

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 稳定 | 直调系统原生 API，不引入第三方桥接层，减少崩溃点 |
| 高效 | 截图走 ScreenCaptureKit 硬件加速管线，遮罩层使用 Core Animation |
| 快速 | 唤起到遮罩出现 <100ms，松手到剪贴板复制 <50ms |

## 二、技术选型

### 2.1 全局快捷键：Carbon Event Manager

**选型理由**：
- macOS 上唯一能在不抢占前台焦点的情况下注册全局热键的稳定方案
- 不依赖 NSEvent，app 后台运行时仍可触发
- Ice、Hammerspoon、CleanShot X 等成熟工具均采用此方案
- 响应延迟 <10ms

**关键 API**：
- `RegisterEventHotKey()` — 注册热键
- `UnregisterEventHotKey()` — 注销热键
- `InstallEventHandler()` — 安装事件回调

**权限要求**：辅助功能（Accessibility）

### 2.2 截图引擎：SCScreenshotManager + CGWindowList

**截图策略（双轨制）**：

| 场景 | API | 说明 |
|------|-----|------|
| 单帧截图（主要路径） | `SCScreenshotManager.captureImage` | macOS 14+ 原生 API，直接获取单帧图像，无需启动 stream |
| 窗口列表枚举 | `SCShareableContent` | 获取屏幕、窗口、应用列表，用于智能吸附 |
| 兜底方案 | `CGWindowListCreateImage` | 老版本兼容或特殊场景使用 |

**为什么选 SCScreenshotManager**：
- 硬件加速，性能最优
- 支持指定 display、window、region 三种过滤维度
- 直接返回 CGImage，无需自己处理 sample buffer
- 苹果官方推荐（参考 Apple 官方示例项目 "Capturing screen content in macOS"）

**权限要求**：屏幕录制权限

### 2.3 全屏遮罩：NSPanel + .nonactivatingPanel

**关键配置**（参考 Apple Developer Forums 实测方案）：

```swift
let panel = NSPanel(
    contentRect: screenFrame,
    styleMask: [.nonactivatingPanel, .borderless],
    backing: .buffered,
    defer: false
)
panel.isFloatingPanel = true
panel.hidesOnDeactivate = false
panel.level = .screenSaver  // 关键：必须在 screenSaver 级别才能覆盖全屏 app
panel.collectionBehavior = [
    .canJoinAllSpaces,
    .canJoinAllApplications,
    .fullScreenAuxiliary,
    .stationary
]
panel.isOpaque = false
panel.backgroundColor = .clear
panel.ignoresMouseEvents = false
```

**为什么用 NSPanel 而非 NSWindow**：
- `.nonactivatingPanel` 不会激活 app，不会导致其他 app 退出全屏
- `canBecomeKey = false` 可避免抢占键盘焦点
- `.screenSaver` level（1000）才能覆盖全屏应用（.floating=3、.statusBar=25 都不行）

### 2.4 标注画布：Core Graphics + NSView

**选型理由**：
- 标注是高频交互场景，需要像素级控制
- Core Graphics 性能最优，直接绘制到 layer
- 支持 CAShapeLayer 实现标注元素的拖拽二次编辑
- SwiftUI Canvas 性能不够，且与拖拽手势集成复杂

**实现方案**：
- 每个标注元素 = 一个 CAShapeLayer 子类
- 父视图管理所有 layer 的层级、选中状态
- 拖拽时直接修改 layer.frame，无重新绘制开销

### 2.5 剪贴板：NSPasteboard

```swift
let pasteboard = NSPasteboard.general
pasteboard.clearContents()
pasteboard.writeObjects([nsImage])
```

### 2.6 应用类型：双形态架构（托盘 + 主窗口）

**Info.plist 配置**：
```xml
<key>LSUIElement</key>
<true/>
```

**形态说明**：
- 默认以 LSUIElement 形式运行，Dock 不显示图标，仅托盘常驻
- 用户从托盘菜单「偏好设置」打开主窗口时，动态调整 Dock 图标显示
- 主窗口关闭后恢复 LSUIElement 状态
- 主窗口承载设置页、（后期）账户/订阅，不承载截图核心功能

应用核心状态流转：

```
                    ┌─────────────┐
                    │   Idle      │ ← 托盘常驻，监听快捷键
                    └──────┬──────┘
                           │ Shift+Z
                           ▼

                    │  Capturing  │ ← 全屏遮罩，鼠标框选，工具栏浮出
                    │             │   信息条显示尺寸/圆角/阴影
                    └──────┬──────┘
                           │ 松开鼠标
                    ┌──────┴──────┐
                    │             │

                    │             │
                    ▼             ▼
              ┌──────────┐  ┌──────────┐
              │ Copying  │  │Annotating│ ← 进入标注模式（双层工具栏）
              └────┬─────┘  └────┬─────┘
                   │             │ 完成/Enter
                   ▼             ▼
              ┌─────────────────────┐
              │      Finish         │
              │  复制到剪贴板/保存    │
              └─────────┬───────────┘
                        │
                   ┌────┴────┐
                   │         │
                   ▼         ▼点📌
              ┌─────────┐  ┌─────────┐
              │  Idle   │  │ Pinning │ ← 贴图常驻（双击→Annotating）
              └─────────┘  └────┬────┘

                                  ▼

                            │Annotating│ ← 重新标注贴图
                            └──────────┘
```

**状态说明**：
- `Capturing`：框选阶段，右下角白色胶囊工具栏实时跟随
- `Annotating`：标注阶段，工具栏移至选区下方，变为双层结构
- `Pinning`：贴图常驻阶段，可拖动/双击编辑/右键菜单

### 3.3 普通录屏与录音转写边界

| 能力 | 普通录屏 | 录音转写 |
| --- | --- | --- |
| 主要输出 | 屏幕视频 MP4 | 本地音频分段、逐字稿；可选 AI 纪要 |
| 默认音源 | 系统声音 | 系统声音 + 麦克风，可分别开关 |
| 文件策略 | 单次录制完成后导出 | 分轨、分段、持续更新清单 |
| 网络依赖 | 无 | 录音无；会后转写服务可能有，AI 纪要可选 |
| 异常恢复 | 以当前普通录屏能力为准 | 必须恢复所有已完成分段 |

两条链路不得共用同一个 AVAssetWriter 或状态机。录音转写复用系统采集经验和 UI 样式，但使用独立 `MeetingRecorder`。详细设计见[会议记录技术设计-MVP.md](./会议记录技术设计-MVP.md)。

### 3.4 截图流程详解

**唤醒到遮罩出现（<100ms）**：

1. Carbon 收到 Shift+Z 回调（~5ms）
2. 状态机切到 Capturing
3. 立即创建 OverlayPanel 并 orderFrontRegardless（~20ms）
4. 遮罩内立即响应鼠标事件，开始框选
5. 后台异步触发 SCScreenshotManager.captureImage 获取屏幕快照（~50ms）
6. 快照到达后，将遮罩背景替换为快照（实现"冻结画面"效果）

**框选到复制（<50ms）**：

1. 松开鼠标 → 获取选区 rect
2. 从已缓存的屏幕快照裁剪目标区域（~5ms）
3. 写入 NSPasteboard（~10ms）
4. 关闭遮罩，状态机回到 Idle

## 四、关键技术难点与解决方案

### 4.1 屏幕录制权限引导

**问题**：macOS 屏幕录制权限首次授权后，app 必须重启才能生效

**解决方案**：
- 首次启动检测 `CGPreflightScreenCaptureAccess()`
- 未授权时弹出引导窗口，配图说明操作步骤
- 提供"打开系统设置"按钮，跳转到对应面板
- 用户完成授权后提示重启 app
- 使用 `CGRequestScreenCaptureAccess()` 主动触发系统弹窗

### 4.2 辅助功能权限引导

**问题**：全局快捷键依赖辅助功能权限

**解决方案**：
- 检测 `AXIsProcessTrusted()`
- 未授权时引导用户到"隐私与安全性 > 辅助功能"
- 使用 `AXIsProcessTrustedWithOptions` 主动触发系统弹窗

### 4.3 多显示器与坐标系

**问题**：多显示器场景下，坐标原点、缩放因子、HiDPI 处理复杂

**解决方案**：
- 使用 `NSScreen.screens` 获取所有屏幕
- 每个显示器独立创建遮罩 panel
- 坐标统一使用全局坐标系（Cocoa 坐标，左下角原点）
- 截图时根据 display ID 调用 SCScreenshotManager

### 4.4 Retina 与像素对齐

**问题**：Retina 屏 2x 渲染，截图需保持像素清晰

**解决方案**：
- 截图尺寸 = 逻辑尺寸 × backingScaleFactor
- 选区 rect 按 pixel 对齐（使用 CGRectIntegral）
- 标注 layer 的 contentsScale = window.backingScaleFactor

### 4.5 智能窗口吸附

**问题**：鼠标悬停时需识别当前窗口边界

**解决方案**：
- 通过 `SCShareableContent.excludingDesktopWindows(false, onScreenWindowsOnly: true)` 获取窗口列表
- 每个 window 有 frame 属性
- 鼠标移动时计算当前点所在的 window，高亮其 frame
- 吸附阈值：鼠标距离窗口边缘 <5px 时自动对齐

## 五、性能优化策略

### 5.1 启动优化

- 托盘 app 不显示主窗口，启动开销极低
- ScreenCaptureKit 初始化延迟到首次截图时
- 窗口列表缓存，500ms 刷新一次

### 5.2 内存优化

- 截图快照在遮罩关闭后立即释放
- 标注元素使用 CAShapeLayer，避免位图缓存
- 贴图窗口在不可见时释放图像数据

### 5.3 响应优化

- 框选过程中不触发截图，仅绘制选区框
- 标注绘制使用 display link 同步，避免撕裂
- 所有耗时操作（截图、编码）放在后台队列

## 六、系统权限清单

| 权限 | 用途 | 触发时机 | API |
|------|------|---------|-----|
| 屏幕录制 | 截图、窗口识别 | 首次截图 | `CGRequestScreenCaptureAccess()` |
| 辅助功能 | 全局快捷键 | 首次启动 | `AXIsProcessTrustedWithOptions()` |
| 麦克风 | 录音转写中采集本机声音 | 首次启用麦克风 | `AVCaptureDevice.requestAccess(for: .audio)` |

录音转写使用系统声音时需要屏幕录制权限。麦克风用途说明必须通过 `NSMicrophoneUsageDescription` 写入生成的 Info.plist；两类权限按用户选择的音源分别申请。

## 七、兼容性

- 最低系统版本：macOS 14.0（Sonoma）
  - SCScreenshotManager 需要 macOS 14+
  - ScreenCaptureKit 完整功能需要 macOS 14+
- 推荐：macOS 15.0+（Sequoia）
- 架构：Apple Silicon + Intel 通用

## 八、第三方依赖

核心本地能力保持零第三方代码依赖，均使用系统原生框架实现：

- ScreenCaptureKit
- CoreGraphics
- AppKit
- Carbon（仅 EventHotKey 部分）
- Vision（阶段二 OCR 使用）
- AVFoundation（普通录屏与会议音频）
- Security/Keychain（模型 API Key）
- URLSession（连接用户配置的 ASR/LLM 服务）

录音转写和可选 AI 纪要会调用用户配置的外部 HTTP API，但不要求在客户端引入供应商 SDK。
