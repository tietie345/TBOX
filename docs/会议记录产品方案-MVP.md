# TBOX 录音转写与 AI 会议纪要产品方案（MVP）

> 文档状态：已确认，作为后续产品与开发依据  
> 创建时间：2026-08-13  
> 核心方案：本地可靠录音 + 会后转写 + 可编辑逐字稿；AI 会议纪要作为可选增强

## 一、产品目标

在 TBOX 中增加独立的录音转写能力。录音首先可靠保存在本机；结束后，通过转写服务生成带时间戳和说话人的逐字稿。用户接入大语言模型后，可以再按照指定模板生成 AI 会议纪要。没有 LLM 时，录音转写仍然是完整可用的产品能力。

```text
开始录音转写
  → 本地分轨、分段录音
  → 结束录音
  → 会后转写
  → 校对逐字稿与说话人
  → 可选：选择纪要模板并生成 AI 会议纪要
  → 编辑并导出逐字稿或纪要
```

### 1.1 核心价值

- 录音不依赖网络，不因模型或服务异常丢失。
- 保留逐段时间戳，支持从文字定位原始录音。
- 稳定区分“我”和“其他参会人”，并允许校正说话人姓名。
- 逐字稿与 AI 纪要分离，修订逐字稿后可以重新生成纪要。
- 录音转写可以独立使用；AI 纪要兼容用户自己的 LLM 服务，降低供应商绑定。

### 1.2 MVP 成功标准

- 连续录制 2 小时，不丢失已经完成落盘的录音分段。
- 无网络时可以正常开始、暂停、继续和结束录音。
- 转写失败后可以从失败分段继续，无需重新上传整场会议。
- 逐字稿包含时间戳、说话人和正文，并可直接编辑。
- 配置 LLM 后可以通过内置或自定义模板生成 AI 纪要，失败不会覆盖既有结果。

## 二、版本范围

### 2.1 录音转写核心（必须实现）

- 独立的录音转写入口、会话列表和详情。
- 系统声音、麦克风分别开关、分轨保存、固定时长分段落盘。
- 录制计时、音源状态、暂停、继续和结束。
- 异常退出后的未完成会议检测与恢复提示。
- 独立配置录音转写服务；AI 纪要模型为可选配置。
- 会后分段转写、进度展示、失败重试和断点续传。
- 带时间戳的逐字稿展示与编辑。
- 说话人重命名、批量替换和合并。
- 复制及导出逐字稿 Markdown、TXT。
- 本地会话删除、原始录音保留策略和隐私提示。

### 2.2 AI 会议纪要增强（可选）

- 配置 LLM、内置纪要模板和自定义模板。
- 根据已校对逐字稿生成结构化纪要。
- 重新生成和纪要版本保留。
- 纪要复制及导出 Markdown、TXT。

### 2.3 MVP 明确不做

- 实时字幕或实时纪要。
- 自动加入 Zoom、腾讯会议、飞书会议等会议房间。
- 通过声纹自动识别真实姓名。
- 团队协作、云端同步和多人编辑。
- 自动发送纪要或自动创建第三方任务。
- 默认录制屏幕视频；普通录屏继续由现有功能负责。
- TBOX 官方代付模型费用；MVP 使用用户自备 API。

## 三、关键产品边界

### 3.1 转写服务与 AI 纪要模型

录音转写和 AI 会议纪要是两个独立层次，不能用一个模糊的“模型 API”配置代替：

| 能力 | 作用 | 必要输出 |
| --- | --- | --- |
| 录音转写服务（ASR） | 将音频转换为文字 | 分段文字、开始/结束时间；说话人分离为可选能力 |
| AI 纪要模型（LLM） | 根据已完成的逐字稿整理纪要 | 结构化 Markdown 文本；可不配置 |

聊天模型不默认具备音频转写、时间戳和说话人分离能力。ASR 和 LLM 必须分别配置、分别测试；未配置 LLM 不影响录音转写。

### 3.2 说话人定义

- 麦克风轨默认标记为“我”。
- 系统声音轨默认标记为“其他参会人”。
- ASR 支持说话人分离时，可进一步产生“说话人 1、说话人 2”等临时身份。
- 用户可以将临时身份改为真实姓名，并批量作用于整场会议。
- 远端声音通常已被会议软件混音，MVP 不承诺准确识别每个人的真实身份。

## 四、信息架构

客户端主窗口新增一级页面“录音转写”，设置中新增“模型服务”。

```text
录音转写
├── 开始新录音转写
├── 进行中的录音转写
├── 最近录音转写
└── 录音转写详情
    ├── 逐字稿
    ├── 逐字稿
    ├── AI 会议纪要（可选）
    └── 录音与转写信息

设置
└── 模型服务
    ├── 语音识别服务
    ├── 纪要生成模型
    └── 数据与保留策略
```

菜单栏增加“开始录音转写…”。录制中提供“打开录音控制条”和“结束录音转写”。

## 五、核心用户流程

### 5.1 首次配置

```text
打开设置 → 模型服务
  → 配置录音转写服务 → 测试连接
  → 可选：配置 AI 纪要模型 → 测试连接
  → 保存
```

未配置转写服务时仍可录音，结束后保留“待转写”状态。未配置 LLM 时仍可查看、编辑和导出逐字稿。

### 5.2 开始录音转写

```text
点击“开始新录音转写”
  → 输入标题（可跳过，默认按时间命名）
  → 选择系统声音、麦克风
  → 检查权限和音量
  → 展示录音与隐私提示
  → 开始记录
```

- 至少选择一个音频来源。
- 选择系统声音时检查屏幕录制权限。
- 选择麦克风时检查麦克风权限，并允许选择输入设备。
- 权限不足时不开始录制，但保留用户填写的内容。
- 提示用户遵守所在地法律并取得参会者同意。

### 5.3 录音转写进行中

会议控制条展示：

- 红色录制状态和累计时长。
- 系统声音、麦克风的启用与实时音量状态。
- 暂停/继续、结束录音。
- 本地保存状态：正常、写入延迟或失败。

暂停期间不写入静音占位；恢复后展示时间轴连续，同时在会话事件中保留暂停区间。

### 5.4 结束与转写

```text
结束录音
  → 完成当前录音分段
  → 会话进入“待转写”
  → 自动或手动开始转写
  → 按分段显示进度
  → 合并完整逐字稿
  → 进入校对页面
```

- 默认自动转写可以关闭。
- 转写可在后台进行，关闭主窗口不应中止。
- 退出应用时保留任务状态，下次启动继续。
- 单个分段失败不影响其他分段，提供“重试失败分段”。

### 5.5 校对逐字稿

逐字稿按段展示：

```text
[00:12:08–00:12:16] 客户张总
第一期我们希望先解决内部协作的问题。
```

支持编辑正文和时间、点击时间戳播放、修改说话人、合并说话人、拆分/合并/删除段落、全文搜索。MVP 使用稳定的分段列表编辑，不实现复杂富文本编辑器。

### 5.6 可选：生成 AI 会议纪要

```text
校对逐字稿
  → 选择模板
  → 填写可选上下文
  → 确认发送的服务和内容范围
  → 生成纪要
  → 编辑、复制或导出
```

- 输入以当前保存的逐字稿为准，不直接使用音频。
- 长逐字稿超过模型上下文时，应用先分段提炼再汇总。
- 每次生成创建新版本，不覆盖旧版本。
- 保存模板、模型名称、生成时间和逐字稿版本。

## 六、AI 会议纪要模板

接入 LLM 后提供：

1. 标准会议纪要：主题、参与人、核心讨论、结论、待办。
2. 客户访谈：背景、现状、痛点、需求、异议、机会、后续行动。
3. 销售沟通：目标、预算/时间、决策链、风险、下一步。
4. 需求评审：需求说明、确认项、未决项、风险、负责人。
5. 项目周会：进展、问题、决策、下周计划、待办。
6. 决策与待办：仅提取明确决策和行动项。

自定义模板包括名称、场景说明、系统提示词、输出结构示例、是否引用时间戳、是否要求负责人和截止日期。用户可以复制内置模板修改，但不直接覆盖内置模板。

## 七、转写服务与 AI 模型设置

### 7.1 录音转写服务

| 配置项 | 说明 |
| --- | --- |
| 服务名称 | 用户自定义显示名 |
| API 地址 | 转写接口或兼容服务地址 |
| API Key | 保存到 macOS Keychain |
| 模型名称 | 用户填写 |
| 语言 | 自动检测或固定语言 |
| 时间戳能力 | 无、分段、逐词 |
| 说话人分离 | 服务是否支持 |
| 单文件限制 | 大小或时长，用于调整上传分片 |

连接测试必须验证鉴权、模型可用性和必要能力，不能只验证域名可访问。

### 7.2 AI 纪要生成模型（可选）

| 配置项 | 说明 |
| --- | --- |
| 服务名称 | 用户自定义显示名 |
| Base URL | 默认按 OpenAI-compatible 接口设计 |
| API Key | 保存到 macOS Keychain |
| 模型名称 | 用户填写 |
| 上下文长度 | 判断是否启用分段汇总 |
| 温度 | 默认低随机性 |
| 自定义系统提示词 | 界面明确其与模板的优先级 |

### 7.3 配置规则

- API Key 默认隐藏，只允许替换或删除，不回显完整值。
- 非敏感配置保存在本机，密钥仅存 Keychain。
- 默认只允许 HTTPS；本机服务可显式允许 HTTP。
- 删除配置前提示受影响的待处理会议。

## 八、会议状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| recording | 正在录音 | 暂停、结束 |
| paused | 已暂停 | 继续、结束 |
| interrupted | 异常中断且存在已保存音频 | 恢复处理、结束录音转写 |
| pendingTranscription | 录音完成，尚未转写 | 开始转写 |
| transcribing | 正在转写 | 查看进度、取消任务 |
| transcriptionFailed | 部分或全部失败 | 重试失败分段 |
| readyForReview | 逐字稿已生成 | 校对、生成纪要 |
| summarizing | 正在生成纪要 | 查看状态、取消请求 |
| completed | 录音转写完成，至少存在逐字稿 | 编辑、导出；可选生成 AI 纪要 |

取消网络任务不会删除本地录音、逐字稿或既有 AI 纪要。

## 九、数据、隐私与删除

- 原始录音、逐字稿和可选 AI 纪要默认保存在本机。
- 只有用户开始转写时，才向所配置的 ASR 上传音频分段。
- 只有用户开始生成时，才向所配置的 LLM 发送逐字稿和模板信息。
- TBOX 不把会议内容发送到其他未选择的服务。

原始录音保留选项：永久保留；转写成功后保留 7 天或 30 天；转写成功后立即删除。默认永久保留，由用户主动删除，避免自动清理造成不可恢复的损失。

删除录音转写会话前列出将删除的录音、逐字稿和纪要，并二次确认。删除单个 AI 纪要版本不影响逐字稿和录音；清除 API 配置不删除已有会话。

## 十、异常与恢复

| 场景 | 产品行为 |
| --- | --- |
| 断网 | 继续录音；会话进入待转写，网络恢复后重试 |
| ASR 鉴权失败 | 停止新请求，保留进度并引导更新密钥 |
| 单段转写失败 | 标记失败段，其余继续 |
| LLM 生成失败 | 保留逐字稿和旧 AI 纪要，可重试 |
| 磁盘空间不足 | 明确告警并安全结束当前分段 |
| 音频设备拔出 | 保留另一音轨，提示重新选择设备 |
| 应用崩溃/强退 | 下次启动恢复已完成分段 |
| 系统睡眠 | 记录中断，唤醒后提示继续或结束 |

## 十一、验收标准

### 11.1 录音可靠性

- 系统声音与麦克风可独立启用，并保存为可单独播放的音轨。
- 录制 2 小时后，所有已结束分段均可读取和播放。
- 强制结束应用后，除正在写入的最后分段外，其他分段不损坏。
- 暂停恢复后时间轴正确，无负时间或大段重复。

### 11.2 转写与编辑

- 支持分段提交、进度展示和失败段重试。
- 合并后的时间戳单调递增。
- 说话人改名和合并可作用于全文。
- 编辑后退出再进入，内容保持一致。

### 11.3 纪要与安全

- 六种内置模板和自定义模板均可复用。
- 超过上下文的逐字稿自动分段提炼。
- 重新生成产生新版本，不覆盖历史版本。
- API Key 不出现在普通配置、日志和错误提示中。
- 无转写服务、无 LLM 配置或无网络不影响本地录音；无 LLM 仍可使用逐字稿。

## 十二、后续版本候选

- 实时转写和字幕。
- 降噪、回声消除与静音段裁剪。
- 声纹档案与常用参会人识别。
- 日历和会议软件集成。
- 一键同步到飞书、Notion、邮件或任务系统。
- 团队模板、共享会议与权限管理。
- 可选屏幕视频与文字时间轴联动。

## 十三、已确认决策

1. 录音转写 MVP 采用会后转写，不做实时转写。
2. 原始内容先可靠写入本地，网络和模型不进入录音关键链路。
3. 默认只处理音频，不默认录制屏幕视频。
4. ASR 和 LLM 分别配置、分别验证。
5. 逐字稿是 AI 纪要生成的事实输入，允许先校对再生成。
6. AI 纪要版本化保存，不覆盖历史结果。
7. 录音转写不依赖 LLM；AI 纪要使用用户自备 API，不依赖 TBOX 自建模型服务。
