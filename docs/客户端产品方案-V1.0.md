## 一、产品背景

TBOX 已具备截图工具的实际能力。产品化阶段还需要一个用户可见的客户端，用于承载账户、快捷键、订阅、充值、设备和服务状态等管理功能。

用户下载时只获得一个完整应用安装包。截图工具随客户端一起安装、启动和更新，用户不需要理解或管理独立的后台组件。

## 二、产品定位

客户端定位为 **TBOX 的账户与工具控制台**，核心职责包括：

- 展示截图服务运行状态并提供统一入口。
- 配置全局快捷键和本机使用偏好。
- 登录、退出及维护用户资料。
- 查看订阅方案、续费日期和会员权益。
- 购买订阅或充值 AI 点数。
- 查看和管理已授权设备。
- 展示屏幕录制、辅助功能等系统权限状态。
- 管理本地录音、逐字稿和可选的 AI 会议纪要。
- 配置用户自备的录音转写服务与 AI 纪要模型。
- 统一完成客户端和截图服务的版本更新。

客户端不承担截图画面处理。截图、录屏、标注、贴图等高频操作继续由原生后台服务完成，以确保唤起速度和操作性能。

## 三、产品形态

采用 **一个安装包、一款应用、两种界面形态**：

| 形态 | 用户感知 | 主要职责 |
| --- | --- | --- |
| 客户端主窗口 | 可见 | 状态、快捷键、记录、模型和账户管理 |
| 菜单栏与截图服务 | 弱感知 | 全局快捷键监听、截图、录屏、录音转写、标注、贴图、OCR |

### 运行规则

1. 用户安装并首次打开 TBOX。
2. 客户端引导用户完成屏幕录制和辅助功能授权。
3. 截图服务自动启动并常驻菜单栏。
4. 用户关闭主窗口后，截图服务继续运行。
5. 用户可通过菜单栏再次打开客户端主窗口。
6. 更新应用时，客户端和截图服务作为一个整体更新。

## 四、信息架构

客户端保持五个克制的一级入口：“状态、快捷键、记录、模型、账户”。普通录屏文件和录音转写统一在“记录”中维护；订阅、点数和设备并入“账户”，不再拆成独立仪表盘页面。

### 4.1 状态

- 截图服务运行状态和全局快捷键。
- 屏幕录制、辅助功能等系统权限状态。
- 开机启动、完成提示和自动更新等常用设置。
- 立即开始截图的单一主操作。

### 4.2 快捷键

- 录制和修改全局唤起快捷键。
- 检测快捷键与系统或其他应用的冲突。
- 恢复默认快捷键 `⌃⇧A`。
- 展示截图过程中的固定快捷操作。
- 配置开机启动、完成提示和选区行为。

首个版本建议继续坚持“一个全局快捷键走天下”，不向用户暴露大量独立功能快捷键。

### 4.3 记录

- 分页维护普通录屏文件和录音转写会话。
- 展示文件名称、保存时间、时长、大小和本地路径。
- 普通录屏支持播放、在访达中定位和删除。
- 录音转写展示录音中、待转写、转写中、失败、待校对和已完成状态。
- 支持开始转写、重试失败分段、查看进度和打开逐字稿。
- 展示本机空间占用和原始录音保留策略。

普通录屏与录音转写继续使用独立的底层写入链路。“记录”只在客户端界面统一维护文件和状态，不合并两者的录制实现。

### 4.4 模型

- 独立配置录音转写服务（ASR）和可选的 AI 纪要模型（LLM）。
- 保存服务地址、模型名称和必要能力选项。
- API Key 写入 macOS Keychain，不写入普通设置。
- 分别测试鉴权、模型和必要能力。
- 未配置服务不影响本地录音；没有 ASR 时保留为“待转写”，没有 LLM 时仍可使用完整逐字稿。

### 4.5 账户

- 用户头像、昵称、邮箱和用户 ID。
- 登录方式与账户状态。
- 当前订阅方案、价格和续费日期。
- AI 点数余额和充值入口。
- 已授权设备数量和当前设备状态。
- 退出登录和注销账户入口。

订阅权益与点数余额保持两个独立概念，但在同一账户页面中管理：

- 订阅用于解锁高级功能和每月固定权益。
- 点数用于翻译、文字处理等有实际云端成本的 AI 功能。
- 用户主动购买的点数永久有效。
- 会员按月赠送的点数可以按月清零，界面中必须明确标注。

完整边界和验收标准见[录音转写专项方案](./会议记录产品方案-MVP.md)。

## 五、核心用户流程

### 5.1 首次安装

```text
下载安装包
  → 打开 TBOX
  → 阅读核心能力说明
  → 授予屏幕录制权限
  → 授予辅助功能权限
  → 设置或接受默认快捷键
  → 登录或跳过
  → 截图服务自动运行
```

允许用户跳过登录并使用基础截图能力。需要订阅或 AI 点数的功能再触发登录，避免首次使用门槛过高。

### 5.2 修改快捷键

```text
打开客户端
  → 快捷键
  → 点击当前组合键
  → 按下新组合键
  → 自动检测冲突
  → 保存
  → 即时同步到截图服务
```

### 5.3 购买订阅

```text
会员与充值
  → 选择月付或年付
  → 查看权益与价格
  → 确认购买
  → 完成支付
  → 服务端更新权益
  → 客户端和截图服务即时生效
```

### 5.4 AI 点数不足

```text
用户发起 AI 功能
  → 检查点数
  → 点数不足时保留当前截图结果
  → 弹出轻量充值提示
  → 打开客户端充值页
  → 支付完成
  → 返回并继续原操作
```

充值过程不应使用户丢失已经框选或识别的内容。

### 5.5 录音转写

```text
开始录音转写
  → 本地分轨、分段录音
  → 结束录音
  → 使用转写服务会后转写
  → 校对逐字稿和说话人
  → 可选：使用 LLM 生成 AI 会议纪要
  → 编辑、复制或导出
```

录音转写的录音关键链路不依赖网络。未配置转写服务或断网时仍可完整录音；未配置 LLM 时仍可查看、编辑和导出逐字稿，只是不能自动生成 AI 会议纪要。

## 六、权限与数据边界

### 6.1 只保存在本机

- 快捷键配置。
- 截图和录屏内容。
- 标注预设和工具偏好。
- 保存路径与导出格式。
- 最近使用记录。
- 录音转写原始音频、转写任务状态和逐字稿。
- 可选的 AI 会议纪要版本、用户自定义纪要模板和模型非敏感配置。
- 非必要的操作日志。

### 6.2 需要服务端保存

- 用户账户和登录身份。
- 订阅状态和权益有效期。
- AI 点数余额及变动记录。
- 订单和支付状态。
- 授权设备标识。
- 必要的风控和服务审计记录。

### 6.3 安全原则

- 登录令牌存入 macOS Keychain，不写入普通配置文件。
- 用户配置的模型 API Key 同样存入 macOS Keychain。
- 截图服务只能读取运行所需的最小账户状态。
- 权益状态使用签名数据或本机安全缓存，避免被直接修改。
- 云端 AI 能力只上传用户明确提交处理的内容。
- 上传 AI 服务前显示明确说明，并提供关闭云端能力的选项。
- 录音仅在用户发起转写时发送给选定的 ASR；逐字稿仅在用户发起生成 AI 纪要时发送给选定的 LLM。
- 退出登录后清理令牌，但保留用户本机的截图偏好。

## 七、订阅与支付方案

支付架构取决于分发方式。

### 方案 A：官网直接下载

- 使用自建账户和支付系统。
- 可接入微信支付、支付宝或 Stripe 等渠道。
- 客户端通过服务端接口获取订阅和点数状态。
- 更新可使用 Sparkle 或自建更新机制。

优点是商业策略和支付方式更灵活；缺点是需要自行负责支付合规、退款、发票和订阅通知。

### 方案 B：Mac App Store

- 订阅和数字点数通常需要使用 Apple 应用内购买。
- 使用 StoreKit 2 获取交易并恢复购买。
- 服务端验证交易并下发跨设备权益。
- 应用更新由 App Store 管理。

优点是支付信任和更新体验统一；缺点是存在审核、抽成和功能限制。

### 初步建议

如果主要面向国内效率工具用户并希望快速验证付费，优先评估官网分发；同时在技术层将支付渠道封装为独立模块，避免账户权益与具体支付方式强绑定。

## 八、技术架构建议

延续当前的原生 macOS 技术路线：

| 模块 | 建议技术 | 说明 |
| --- | --- | --- |
| 客户端界面 | SwiftUI | 账户、设置、订阅和设备管理 |
| 截图服务 | AppKit + CoreGraphics | 保证全局截图性能和原生交互 |
| 进程通信 | XPC 或受控本地通信 | 同步快捷键、权益和服务状态 |
| 登录凭证 | Keychain | 保存访问令牌和刷新令牌 |
| 模型密钥 | Keychain | 保存用户自备 ASR/LLM API Key |
| 本机设置 | UserDefaults / JSON | 快捷键和工具偏好 |
| 录音转写会话 | Application Support + JSON/音频文件 | 分段录音、逐字稿、可选纪要及恢复数据 |
| 录音采集 | ScreenCaptureKit + AVAudioEngine | 系统声音与麦克风分轨采集 |
| 会后处理 | URLSession + Provider 适配器 | 分段转写和可选 AI 纪要生成 |
| 账户服务 | HTTPS API | 用户、订阅、点数和设备 |
| 实时权益更新 | 短轮询或推送 | 支付完成后尽快生效 |
| 自动更新 | 按分发渠道确定 | 官网分发或 App Store 更新 |

### 客户端与截图服务通信

客户端向截图服务同步：

- 快捷键配置。
- 登录状态。
- 当前权益摘要。
- AI 点数是否可用。
- 开机启动和本机偏好。

截图服务向客户端上报：

- 服务运行状态。
- 当前版本。
- 权限状态。
- 快捷键冲突。
- 需要登录、续费或充值的业务事件。

不要让截图的基础链路依赖网络。服务端不可用时，已安装用户仍应能够完成基础截图、标注、保存和复制。

## 九、离线与异常策略

- 无网络时允许使用基础功能。
- 已验证的订阅权益应提供合理的离线宽限期。
- 权益过期但无法联网校验时，先提示用户联网，不立即破坏当前操作。
- 截图服务异常时，客户端提供“重新启动服务”操作。
- 快捷键冲突时保留旧快捷键，直到新快捷键保存成功。
- 支付处理中不得重复扣款；订单以服务端最终状态为准。
- AI 请求失败时不扣点，或自动原路退回已预扣点数。
- 录音转写不依赖网络；转写或 AI 纪要失败保留本地数据及已完成进度。
- 应用异常退出后扫描未完成录音转写会话，恢复已完成录音分段并由用户决定后续处理。

## 十、版本范围

### 客户端 V1.1

- 登录与退出。
- 概览页。
- 快捷键配置和冲突检测。
- 订阅状态展示。
- AI 点数余额和充值入口。
- 当前设备及权限状态。
- 截图服务状态和自动启动。
- 基础自动更新能力。
- 录音转写入口、会话列表和详情。
- 本地双轨分段录音、异常恢复和录音保留策略。
- 用户自备转写服务/LLM 配置与 Keychain 密钥存储。
- 会后转写、逐字稿编辑和版本化导出。
- 可选 AI 会议纪要模板和版本化生成。

### 后续版本

- 多设备解绑和远程下线。
- 账单、发票和退款自助管理。
- 团队订阅和席位管理。
- 云端配置同步。
- 邀请奖励或兑换码。
- 更完整的账户安全中心。
- 实时会议字幕、会议软件集成、声纹识别和团队共享。

## 十一、关键指标

- 首次安装到完成第一次截图的转化率。
- 权限引导完成率。
- 快捷键配置成功率和冲突率。
- 客户端崩溃率与截图服务在线率。
- 免费用户到付费用户的转化率。
- 订阅续费率和取消原因。
- AI 点数购买率与实际消耗率。
- 录音转写成功率、异常恢复率和平均连续录制时长。
- 转写成功率、失败分段重试成功率和逐字稿校对率。
- 从转写完成到纪要生成的转化率。
- 支付完成到权益生效的耗时。

## 十二、待确认事项

1. 首发采用官网分发还是 Mac App Store。
2. 登录方式采用 Apple、手机号、邮箱还是组合方式。
3. 订阅功能边界与免费版限制。
4. AI 点数的定价、消耗规则和有效期。
5. 一个账户允许授权的设备数量。
6. 会员过期后的离线宽限期。
7. 是否在首发版本中支持退款、发票和兑换码。

## 十三、原型说明

配套 HTML 原型位于项目根目录：

- [TBOX-client-prototype.html](../TBOX-client-prototype.html)

原型已包含以下可交互内容：

- 四个一级页面切换。
- 快捷键录制和恢复默认。
- 设置开关。
- 订阅周期切换。
- 三档点数充值和确认弹窗。
- 账户、设备与权限状态。
- 桌面端和窄屏响应式布局。

当前原型已补充“记录”和“模型”两个一级页面：

- “记录”统一维护普通录屏文件、录音转写会话、转写进度和本地存储状态。
- “模型”分别配置录音转写服务（ASR）与可选 AI 纪要模型（LLM），支持 API 地址、模型名称、API Key、能力选项、连接测试和本机保存提示。
- API Key 在正式实现中写入 macOS Keychain；HTML 原型只演示交互，不持久化任何密钥。
