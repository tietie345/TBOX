# 录音转写架构与质量标准

## 目标

录音转写必须优先保证完整性、可恢复性和结果可追溯。界面上的流畅感不能以静默丢字、伪造时间戳或把失败结果当成功结果为代价。

## 正式流水线

```text
麦克风录音（M4A，44.1 kHz，单声道）
  → 文件完整性与有效帧检查
  → WhisperKit / Core ML 本地模型加载
  → 音频转换为 16 kHz 浮点 PCM
  → Energy VAD 按静音边界分块
  → Whisper Large v3 多语言识别
  → 词级时间戳
  → 句末标点、停顿、时长和字数联合分段
  → 原子保存 transcript.json
  → 可编辑逐句视图 / 纯文本视图
```

主引擎为 `WhisperKit 1.1.0`，模型固定为 `large-v3-v20240930_626MB`。它是上游针对 Apple Silicon 支持列表中推荐的 Whisper Large v3 多语言模型（非 Turbo 版）。版本固定在仓库中，防止依赖更新未经验证便改变行为。

## 为什么不再以 Apple Speech 为主引擎

`SFSpeechRecognizer` 适合作为系统集成和轻量识别能力，但应用无法控制它的模型版本、解码参数、上下文、可用性和服务端行为。此前固定 45 秒切片后，任一片段返回空结果会造成整片文字缺失，也无法稳定修复中文断句。

Apple Speech 现在只作为用户可选的兼容路径保留：默认关闭，只有用户在“模型”页面明确允许后，才会在本地模型下载、加载或推理失败时启用。兼容结果必须标注来源，不能与高精度结果混淆。

## 模型管理与隐私

- 模型目录：`~/Library/Application Support/TBOX/Models/`
- 首次下载：约 626 MB，仅下载模型文件，不上传录音。
- 模型就绪后：音频完全在本机处理。
- 兼容路径：默认关闭。用户主动开启后，macOS Speech 是否使用在线服务由系统决定；进入兼容路径时界面会明确提示。
- 录音目录：`~/Library/Application Support/TBOX/Recordings/`
- 转写缓存：与录音相邻的 `*.m4a.transcript.json`。

转写缓存包含录音文件大小和修改时间校验。录音被替换、修改或缓存损坏后，不复用旧结果。写入使用原子操作，避免应用异常退出留下半份“完成结果”。

## 可靠性策略

1. 录音停止后确认文件存在、大小非零且包含有效音频帧。
2. 长录音使用增量读取，避免数小时文件一次性进入内存。
3. VAD 只在静音边界切分，减少句首、句尾丢失。
4. Whisper 解码使用温度回退、压缩率、平均概率、首词概率和静音概率阈值，抑制重复与幻觉。
5. 开启词级时间戳；逐句视图基于真实词时间而不是按字符平均估算。
6. 高精度引擎失败时记录具体错误并降级；两个引擎都失败时明确显示失败，不把录音路径展示成转写正文。
7. 完成结果记录引擎来源。缓存格式升级时提高版本号，避免旧算法结果被误认为新结果。

## 当前边界

- 当前录音源是麦克风，不包含独立的系统声音轨道。
- 当前仅显示单一说话人“我”，尚未集成 SpeakerKit 的说话人分离模型。
- 大模型首次下载和 Core ML 首次设备专用化需要时间；之后会复用本地缓存。
- 大模型文本润色不是识别正确性的前提。后续若增加润色，必须同时保留未经改写的原始转写，禁止用生成式改写覆盖原文。

## 发布前验收门槛

每次修改录音转写后至少验证：

1. 10 秒、2 分钟、30 分钟三种时长；中文、英文、中英混说各一份。
2. 开头立即说话、长停顿、连续讲话、低音量和背景噪声场景。
3. 逐句时间戳单调递增，最后时间不超过音频时长。
4. 不允许出现整段静默丢失；引擎失败必须有用户可见原因。
5. 相同录音重复转写结果应稳定，缓存读取不再次发起识别。
6. 强制中断后原始录音仍可打开，缓存损坏能安全重试。
7. 使用一套固定中文基准录音记录 CER（字错率）。版本发布前不得比上一个稳定版本退化超过 2 个百分点。
8. 完整执行 `./compile.sh`、`./run_smoke_tests.sh`、脚本语法检查、`git diff --check` 和固定证书签名验证。
9. 在固定录音上执行 `TBOX --transcribe-file /absolute/path/audio.m4a`，确认模型下载/复用、本地推理、分句和缓存落盘全链路通过。该诊断模式不打开界面、不请求权限、不上传音频。
