# 录音转写架构与质量标准

## 目标

录音转写必须优先保证完整性、可恢复性和结果可追溯。界面上的流畅感不能以静默丢字、伪造时间戳或把失败结果当成功结果为代价。

## 正式流水线

```text
麦克风录音（CAF，48 kHz，16-bit 单声道 Linear PCM）
  + 系统声音采集（ScreenCaptureKit，48 kHz 双声道 AAC，仅系统输出）
  → 双轨混音为单声道 48 kHz（AudioTrackMixer）
  → 文件完整性与有效帧检查
  → WhisperKit / Core ML 本地模型加载
  → 音频转换为 16 kHz 浮点 PCM
  → Energy VAD 按静音边界分块
  → Whisper Large v3 多语言识别
  → 词级时间戳
  → 句末标点、停顿、时长和字数联合分段
  → 原子保存 transcript.json
  → 可编辑逐句视图 / 纯文本视图
```

主引擎为 `WhisperKit 1.1.0`，模型固定为 `large-v3-v20240930_626MB`。它是上游针对 Apple Silicon 支持列表中推荐的 Whisper Large v3 多语言模型（非 Turbo 版）。版本固定在仓库中，防止依赖更新未经验证便改变行为。

## 为什么不再以 Apple Speech 为主引擎

`SFSpeechRecognizer` 适合作为系统集成和轻量识别能力，但应用无法控制它的模型版本、解码参数、上下文、可用性和服务端行为。此前固定 45 秒切片后，任一片段返回空结果会造成整片文字缺失，也无法稳定修复中文断句。

Apple Speech 现在只作为用户可选的兼容路径保留：默认关闭，只有用户在“模型”页面明确允许后，才会在本地模型下载、加载或推理失败时启用。兼容结果必须标注来源，不能与高精度结果混淆。

## 模型管理与隐私

- 模型目录：`~/Library/Application Support/TBOX/Models/`
- 下载时机：**不在应用启动时静默下载**。首次真正使用转写时弹出体积确认（识别约 626 MB + 说话人识别约 11 MB，合计约 637 MB），用户确认后后台下载；也可在“设置 · 模型”手动下载。可在设置中关闭“首次转写时下载语音模型”。
- 模型就绪后：音频完全在本机处理。
- 模型已安装时**严格本地加载，不发起任何网络请求**：直接用本地模型目录 + 本地 tokenizer 构建管线，不再联网核对 HuggingFace 快照。此前每次转写都要调用 `WhisperKit.download()` 核对快照，网络不可达（如国内直连 huggingface.co）时会超时，表现为“模型加载失败”。仅当模型缺失时才走下载。
- 兼容路径：默认关闭。用户主动开启后，macOS Speech 是否使用在线服务由系统决定；进入兼容路径时界面会明确提示。
- 录音目录：`~/Library/Application Support/TBOX/Recordings/`
- 转写缓存：与录音相邻的 `<录音文件名>.transcript.json`（如 `录音转写_20260101_120000.caf.transcript.json`）。
- 录音归档：转写完成后默认把未压缩录音（`.caf`/`.wav`）转为 AAC（`.m4a`），约 5.76 MB/分钟降至约 0.7 MB/分钟。仅当导出成功且新缓存写入成功后才删除原文件，任何一步失败都保留原录音；可在“设置 · 模型”关闭。

转写缓存包含录音文件大小和修改时间校验。录音被替换、修改或缓存损坏后，不复用旧结果。写入使用原子操作，避免应用异常退出留下半份“完成结果”。

## 双轨录音与系统声音

线上会议里对方的声音只存在于系统输出，麦克风轨抓不到。为此在麦克风轨之外并行采集一路系统声音：

- 采集方式：`SystemAudioRecorder` 用一个仅要音频的 `SCStream`（画面压到 2×2、帧率压到 1 fps，几乎不产生开销）抓系统输出，`excludesCurrentProcessAudio` 保证不会把 TBOX 自己播放的声音混进去。不依赖第三方虚拟声卡。
- 权限：复用“屏幕录制”权限（与截图/录屏同一项）。权限缺失或启动失败时只记日志并降级为仅麦克风轨，**绝不阻断录音主流程**。
- 混音：`AudioTrackMixer` 把两轨归一到 48 kHz 单声道浮点后逐样本相加（各留增益余量后硬限幅），输出仍是 48 kHz 单声道 Linear PCM，与单轨录音格式一致。任一步失败都保留麦克风原文件。
- 暂停语义：录音过程中暂停只中断麦克风轨、不中断系统声音轨；混音时按暂停区间跳过对应的系统声音，因此输出时间轴等于麦克风的“有效录音时间轴”，暂停不会加长输出。
- 开关：设置 · 模型 · 录音输入里的“同时录制系统声音”，缺省开启。

## 可靠性策略

1. 录音停止后确认文件存在、大小非零且包含有效音频帧。
2. 长录音使用增量读取，避免数小时文件一次性进入内存；说话人分离按固定时长窗口分段加载并用说话人质心把各窗编号对齐到全局编号，同样不整段驻留。
3. VAD 只在静音边界切分，减少句首、句尾丢失。
4. Whisper 解码使用温度回退、压缩率、平均概率、首词概率和静音概率阈值，抑制重复与幻觉。
5. 开启词级时间戳；逐句视图优先使用真实词时间。仅当词级对齐不可用时才回退到按字符比例估算，且该情形会标记为「时间估算」，在结果窗口与 txt/md 导出中以 `~` 前缀提示，不与真实时间混淆。
6. 高精度引擎失败时记录具体错误并降级；两个引擎都失败时明确显示失败，不把录音路径展示成转写正文。
7. 完成结果记录引擎来源。缓存格式升级时提高版本号，避免旧算法结果被误认为新结果。

## 当前边界

- 录音源为麦克风轨 + 可选的系统声音轨（见上一节）。系统声音轨依赖“屏幕录制”权限，权限缺失或采集失败时自动降级为仅麦克风轨。
- 双轨混合是简单相加，不做回声消除（AEC）：外放场景下麦克风会同时收进扬声器的声音，同一句话可能被转写两次。线上会议建议佩戴耳机。
- 说话人分离由 SpeakerKit（pyannote）在本机完成：按 5 分钟窗口分离，再用说话人质心把各窗编号合并为全局说话人。跨窗「同一说话人」的余弦距离阈值是经验值（当前 0.5），需按模型与音频标定；阈值不当会把同一人拆开或把不同人合并。
- 大模型首次下载和 Core ML 首次设备专用化需要时间；之后会复用本地缓存。
- 大模型文本润色不是识别正确性的前提。后续若增加润色，必须同时保留未经改写的原始转写，禁止用生成式改写覆盖原文。

## 发布前验收门槛

每次修改录音转写后至少验证：

1. 10 秒、2 分钟、30 分钟三种时长；中文、英文、中英混说各一份。
2. 开头立即说话、长停顿、连续讲话、低音量和背景噪声场景。
3. 逐句时间戳单调递增，最后时间不超过音频时长。
4. 不允许出现整段静默丢失；引擎失败必须有用户可见原因。
5. 相同录音重复转写结果应稳定，缓存读取不再次发起识别。
6. 强制中断后原始录音仍可打开，缓存损坏能安全重试。
7. 使用 `Tools/CER/run_benchmark.sh` 对固定基准录音计算 CER（字错率）。首次用 `--update-baseline` 记录基线，之后版本发布前该脚本必须通过（比基线退化不得超过 2 个百分点）。基准录音与校对文本放入 `Tools/CER/fixtures/`（同名 `<name>.ref.txt` + 录音）。
8. 完整执行 `./compile.sh`、`./run_smoke_tests.sh`、脚本语法检查、`git diff --check` 和固定证书签名验证。
9. 在固定录音上执行 `TBOX --transcribe-file /absolute/path/audio.caf`，确认模型下载/复用、本地推理、分句和缓存落盘全链路通过。该诊断模式不打开界面、不请求权限、不上传音频。
10. 双轨场景：播放一段系统音频（如在线会议回放）同时对着麦克风说话，确认两路声音都进入转写；断开屏幕录制权限后重录，确认自动降级为仅麦克风且录音不中断。
